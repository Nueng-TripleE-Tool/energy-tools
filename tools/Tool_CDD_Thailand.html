ดึงข้อมูลอุณหภูมิรายวัน (Fetch Daily Temperature)

เดือน/ปี พ.ศ. แรกของข้อมูลอุณหภูมิที่ต้องการ · baseline EnPI ควรครอบคลุม ≥ 12 เดือน (ค่าเริ่มต้น 36 เดือนย้อนหลัง) · ที่มา: Open-Meteo ERA5 ย้อนหลังได้ถึงปี 2483
เดือน/ปี พ.ศ. สุดท้าย · ข้อมูล reanalysis ล่าช้าประมาณ 5–7 วัน จึงควรไม่เกินเดือนก่อนหน้า
ยังไม่มีข้อมูล — กดปุ่มดึงข้อมูล หรือโหลดไฟล์ JSON
ตัวแปรเสริมรายวัน (ดึงพร้อมอุณหภูมิเฉลี่ยและ RH) — ติ๊กเฉพาะที่ใช้ ยิ่งมากยิ่งเสี่ยงติด rate limit เร็วขึ้น · ใช้ได้ในแท็บ 2b รายวัน + CSV
ดึงจาก API เป็นรายวันเสมอ (Open-Meteo ไม่มีรายสัปดาห์/รายเดือน) แล้วรวมในเครื่องตามความละเอียดที่เลือก — มีผลกับ "Export CSV ทุกจังหวัด" ปุ่มนี้, "Export CSV จังหวัดนี้" ในแท็บ 2 และรูปแบบเริ่มต้นของแท็บ 2b · รายสัปดาห์นับ จ.–อา. ตาม ISO 8601 สัปดาห์ต้น/ปลายช่วงที่ไม่ครบ 7 วันจะมีคอลัมน์ days กำกับ

หมายเหตุแหล่งข้อมูล: อุณหภูมิเฉลี่ยรายวัน (Tmean) จาก Open-Meteo Historical Weather API (ERA5/ERA5-Land reanalysis ของ ECMWF, กริด ~9–25 กม. ที่พิกัดศูนย์กลางจังหวัด) — ข้อมูลล่าช้าประมาณ 5 วัน จึงตั้งค่าเริ่มต้นถึงเดือนล่าสุดที่ครบเดือน · API ฟรีสำหรับการใช้งานที่ไม่ใช่เชิงพาณิชย์ขนาดใหญ่ (งานเชิงพาณิชย์ปริมาณมากควรสมัคร API plan) · ระบบแบ่งดึงเป็นรายปีเพื่อเลี่ยง rate limit — หากติด limit รายนาที (HTTP 429) เครื่องมือจะรอ ~1 นาทีแล้วดึงต่อเองอัตโนมัติ ไม่ต้องกดซ้ำ อย่าปิดหน้า · ตัวแปรเสริม (Tmax/Tmin · WB จาก API · จุดน้ำค้าง · รังสี · ลม · ฝน · ความดัน) ดึงมาในคำสั่งเดียวกัน ใช้ในแท็บ 2b และ CSV รายวัน · เมื่อเลือก WB จาก API ระบบจะใช้แทนสูตร Stull ทุกแท็บ · วิธีคำนวณ CDD ใช้ daily-mean method: CDDเดือน = Σ max(0, T̄วัน − Tbase) ซึ่งอาจต่างจาก degreedays.net (integration method จากข้อมูลรายชั่วโมง) เล็กน้อย โดยเฉพาะเดือนที่อุณหภูมิแกว่งใกล้ base temperature

คู่มือย่อ (Quick Guide)

① กด "ดึงข้อมูล" ขณะออนไลน์หนึ่งครั้ง (ประมาณ 10–30 วินาที) → ② บันทึก JSON ไว้ใช้ภาคสนามแบบ offline → ③ เลือกแท็บวิเคราะห์: รายจังหวัด / เปรียบเทียบ / แผนที่ / Regression กับข้อมูลพลังงาน (kWh) สำหรับงาน Energy Baseline ตาม ISO 50001 — ทุกแท็บเลือกชนิด CDD/HDD, กระเปาะแห้ง/เปียก และปรับ Base temperature ได้ −25 ถึง +35 °C (ละเอียด 1 °C และพิมพ์ค่าเองได้ เช่น −20 °C สำหรับห้องเย็น) · ปุ่มพิมพ์รายงานอยู่ท้ายแต่ละแท็บ (Ctrl+P ก็ได้)

CDD รายเดือน — รายจังหวัด

ความละเอียด: ตัวเลือกเดียวกับแท็บ 1 — มีผลกับ KPI · กราฟ · ตาราง · CSV ของแท็บนี้
ช่วงวิเคราะห์: จาก ถึง
จังหวัดที่ตั้งอาคาร/โรงงาน — ใช้พิกัดศูนย์กลางจังหวัดดึงอุณหภูมิรายวัน (Open-Meteo ERA5) · ถ้าไซต์อยู่ไกลตัวจังหวัดมากให้ใช้แท็บพยากรณ์+พิกัดไซต์แทน
CDD = ภาระทำความเย็น (ใช้กับ chiller/แอร์) · HDD = ภาระทำความร้อน (แทบไม่ใช้ในไทย) · RH̄ = ความชื้นเฉลี่ย (ภาระแฝง/อบแห้ง)
กระเปาะแห้งใช้กับภาระสัมผัสทั่วไป · กระเปาะเปียก (Stull 2011) ใช้กับ cooling tower/ระบบระเหย เพราะ approach ขึ้นกับ WB
อุณหภูมิฐาน (°C) — ค่าที่อาคารไม่ต้องทำความเย็น · อาคารสำนักงานไทยใช้ 24–26 · โรงงานที่มี internal gain สูง 18–22 · ASHRAE ใช้ 18.3 (65 °F) · ควรหาค่าที่ R² สูงสุดจากแท็บ Regression
💡 ห้องเย็น: ตั้ง base = อุณหภูมิห้อง (เช่น −20 °C) แล้ว DD จะเท่ากับ ΔT·วัน ของกรอบห้องโดยตรง · หอผึ่งน้ำ: เลือกกระเปาะเปียก (Wet-bulb) เพราะเป็นตัวกำหนดสมรรถนะหอจริง

CDDเดือน = Σ max(0, T̄วัน − Tbase) · HDDเดือน = Σ max(0, Tbase − T̄วัน) หน่วย °C·day · เดือนที่ข้อมูลไม่ครบจะแสดงจำนวนวันกำกับ · T̄ = อุณหภูมิเฉลี่ยรายวันที่ 2 ม. จาก ERA5 · กระเปาะเปียกคำนวณจาก T̄ และ RH̄ รายวันด้วยสูตร Stull (2011) ความคลาดเคลื่อน ±0.3–1 °C ในย่าน RH 5–99% · ข้อควรระวัง: เมื่อ base ต่ำกว่าอุณหภูมิรายวันต่ำสุด (~15 °C) ทุกวันจะร่วมคำนวณหมด DD จะเทียบเท่า ΔT·วัน — เหมาะกับห้องเย็น/กระบวนการ sub-ambient แต่การ Optimize base ในย่านนี้จะแยกไม่ออก (R² แบนราบ) ให้กำหนด base = setpoint แทน

CDD รายวัน — Daily Degree Days (รายวัน · รายสัปดาห์ · ค่าเฉลี่ยเคลื่อนที่)

ใช้ค่า ชนิด DD · Sensor · Base temperature ชุดเดียวกับแท็บ 2 (⚡ จากแท็บ 2 — เปลี่ยนได้ที่แท็บ 2 หรือเปิด "ใช้ค่าเดียวกันทุกแท็บ") — ตอนนี้: –
เริ่มต้นตามจังหวัดที่เลือกในแท็บ 2 · เปลี่ยนได้อิสระ
อยู่ในช่วงข้อมูลที่ดึงมา (ค.ศ.) · ค่าเริ่มต้น = 90 วันล่าสุด
ช่วงยาวมาก (> 2 ปี) กราฟจะหนาแน่น แนะนำดูแบบรายสัปดาห์
ใช้ตัวเลือก 2 เมื่อจะเทียบกับ CDD ของกรมอุตุฯ/degreedays.net ที่คิดจาก (Tmax+Tmin)/2 · มีผลเฉพาะกระเปาะแห้ง
รายวัน = ใช้ทำ EnB รายวัน/รายสัปดาห์กับข้อมูลมิเตอร์ที่ละเอียดกว่ารายเดือน · เฉลี่ยเคลื่อนที่ 7 วัน ช่วยตัดสัญญาณรบกวนรายวัน
ช่วงด่วน:

CDDวัน = max(0, T̄วัน − Tbase) · HDDวัน = max(0, Tbase − T̄วัน) หน่วย °C·day (ค่ารายเดือนในแท็บ 2 = ผลรวมของค่ารายวันเหล่านี้) · T̄ = อุณหภูมิเฉลี่ยรายวันที่ 2 ม. จาก ERA5 (Open-Meteo) — ไม่ใช่ค่าเฉลี่ยของ (Tmax+Tmin)/2 แบบสถานีอุตุฯ จึงอาจต่างกันเล็กน้อย · รายสัปดาห์นับสัปดาห์เริ่มวันจันทร์ สัปดาห์ต้น/ปลายช่วงอาจไม่ครบ 7 วัน (แสดงจำนวนวันกำกับ) · ค่าเฉลี่ยเคลื่อนที่ 7 วัน = ค่าเฉลี่ยของวันนั้นกับ 6 วันก่อนหน้า (trailing) · %RH = ค่าเฉลี่ยรายวัน · กระเปาะเปียกจาก Stull (2011)

พยากรณ์อากาศล่วงหน้า 14 วัน (ฝน · CDD · อุณหภูมิ · ความชื้น)

ตัวแปรที่แสดงบนแผนที่พยากรณ์ — ฝนสะสม (งานน้ำ/ไซต์ก่อสร้าง) · อุณหภูมิ/CDD (วางแผนภาระความเย็น/ตรวจวัดหน้างาน)
อุณหภูมิฐานสำหรับ CDD พยากรณ์ (°C) · ใช้ค่าเดียวกับที่ใช้ทำ baseline EnPI (ทั่วไป 24)
จำนวนวันข้างหน้าที่รวมค่า — 3 วันสำหรับวางแผนตรวจวัดหน้างาน · 7–14 วันสำหรับวางแผนภาระ/บำรุงรักษา

ตารางฝนสะสมครบ 77 จังหวัด (เรียงมาก→น้อย)

แหล่งข้อมูล: Open-Meteo Forecast API (โมเดล best-match เช่น ECMWF IFS/GFS ที่พิกัดศูนย์กลางจังหวัด) · ฝน/CDD = ผลรวมของช่วง (CDD คาดการณ์ = Σ max(0, T̄พยากรณ์ − base)) · T̄/RH̄ = ค่าเฉลี่ยของช่วง · เกณฑ์อุตุนิยมวิทยา (ต่อวัน): ฝนเล็กน้อย <10 มม. · ปานกลาง 10–35 มม. · หนัก 35–90 มม. · หนักมาก >90 มม. · ความแม่นยำลดลงตามระยะวันพยากรณ์ (3 วันแม่นกว่า 7 วัน) — ใช้วางแผนงานภาคสนาม/ไซต์งาน ไม่ใช่คำเตือนภัยทางการ

เจาะระดับอำเภอ & หมุดไซต์งาน (Drill-down)

เจาะดูพยากรณ์รายอำเภอของจังหวัดที่เลือก (geocode อำเภอ + Open-Meteo) — ใช้เมื่อไซต์อยู่ไกลตัวเมือง
ใช้ตัวแปร/ช่วง/base เดียวกับแผนที่ด้านบน · ครั้งแรกของแต่ละจังหวัดใช้เวลา ~10–30 วินาที (ค้นพิกัดอำเภอ) ครั้งถัดไปทันที

หมุดไซต์งาน (พิกัดเจาะจง)

ชื่อโรงงาน/ไซต์ลูกค้าที่ต้องการติดตามพยากรณ์เฉพาะจุด (แสดงบนแผนที่และตาราง)
ละติจูด, ลองจิจูด ทศนิยม คั่นด้วยจุลภาค · คัดลอกจาก Google Maps (คลิกขวา → พิกัด) · ประเทศไทย lat 5.6–20.5, lon 97.3–105.6

พิกัดอำเภอค้นอัตโนมัติจาก Open-Meteo Geocoding (จุดศูนย์กลางชุมชนของอำเภอ) · ความละเอียดจริงถูกจำกัดด้วยกริดโมเดล ~9–13 กม. (อุณหภูมิปรับตามความสูงภูมิประเทศถึง ~1 กม.) — อำเภอใกล้กันมากอาจได้ค่าใกล้เคียงกัน · คลิกขวาบน Google Maps แล้วเลือกตัวเลขพิกัดเพื่อคัดลอก lat, lon ของไซต์งาน

ยังไม่มีข้อมูล — กดดึงข้อมูล (ใช้เวลา ~3–5 วินาที, ต้องออนไลน์)

แผนที่สถานีวัดระดับน้ำ

กรองสถานีวัดระดับน้ำตามลุ่มน้ำ (เจ้าพระยา ท่าจีน มูล ชี ฯลฯ) · ที่มา: กรมชลประทาน/สทนช.
กรองสถานีตามจังหวัดที่ตั้งโรงงาน — ใช้ประเมินความเสี่ยงน้ำท่วม/น้ำดิบ
หน่วยงานเจ้าของสถานี (กรมชลประทาน, กรมทรัพยากรน้ำ, หน่วยงานด้านไฟฟ้า) — ค่าจากแต่ละหน่วยงานอาจใช้ระดับอ้างอิงต่างกัน
สถานะระดับน้ำเทียบตลิ่ง — 5 = ล้นตลิ่ง/วิกฤต … 1 = น้ำน้อย · ใช้คัดสถานีที่ต้องเฝ้าระวัง
— ชี้เมาส์ที่จุดสถานี = ดูค่า · คลิก = 📌 ปักหมุดข้อมูล + เปิดกราฟ —

สีตามระดับสถานการณ์น้ำของ สสน. (คลังข้อมูลน้ำแห่งชาติ) เทียบความจุลำน้ำ ณ ตลิ่งต่ำสุดของสถานี · ขนาดจุดใหญ่ = สถานีหลัก (key station) · คลิกจุด = 📌 ปักหมุดข้อมูล + เปิดกราฟ (กด ✕ ล้าง เพื่อปลดล็อก)

วางค่าจาก Excel ได้: คัดลอกทั้งคอลัมน์แล้ววางในช่องแรกของคอลัมน์นั้น ระบบจะกระจายให้อัตโนมัติ (เรียงเดือนเก่า→ใหม่) · ถ้ากรอกผลผลิต ≥ 6 เดือน ระบบจะสลับเป็นแบบจำลอง 2 ตัวแปร E = a + b·ผลผลิต + c·DD อัตโนมัติ (เหมาะกับโรงงานที่ภาระขึ้นกับการผลิต เช่น โรงรีดเหล็ก)

แบบจำลอง OLS: E = a + b·DD (1 ตัวแปร) หรือ E = a + b·ผลผลิต + c·DD (2 ตัวแปร, เลือกอัตโนมัติเมื่อกรอกผลผลิต) · เกณฑ์ทั่วไปของ EnB ที่ใช้ได้ดี: R² ≥ 0.75 และสัมประสิทธิ์มีนัยสำคัญ (|t| ≥ 2) · CV(RMSE) ≤ 20% ตาม IPMVP · การ Optimize base ใช้ได้กับอาคารปรับอากาศ (balance point ในย่าน ~18–28 °C ตาม ASHRAE) — ห้องเย็น/กระบวนการ sub-ambient ให้กำหนด base = setpoint ตายตัว เพราะในย่านต่ำกว่าอุณหภูมิรายวันต่ำสุด R² จะแบนราบแยก base ไม่ออก · หอผึ่งน้ำใช้ DD กระเปาะเปียก (Wet-bulb) ร่วมกับผลผลิตเป็น 2 ตัวแปร
